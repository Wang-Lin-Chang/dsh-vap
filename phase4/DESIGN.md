# VAP Phase 4 设计：跨 NAT 第一步（中继模式）+ 无激励基线 + libp2p 决策

> 立项：外环 Phase 4。让信封跨越 NAT 边界。策略：**中继优先（relay-first）**——先走中继让跨 NAT 通信成立，
> 打洞（STUN/DCUtR）与 libp2p 的取舍做成决策文档（质疑零依赖教条），不仓促引入依赖。
> 核心自我质疑：零依赖是纪律还是教条？本阶段用"中继模式全自研 + 决策文档有根据"来回答。

## 一、中继模式（零依赖自研，node:net TCP）

### relay-server.mjs
- TCP 监听（端口可配）；客户端注册 `{ nodeId, pubKey }`；
- 转发：`{ to, envelope }` → 按 nodeId 查连接转发；中继**只转发不解密不验签**（信封本身有签名保护）；
- 度量：connections / totalBytes / uptime（无激励基线实验的数据源）；
- 安全语义（诚实标注）：中继看得见信封明文（JSON）、看不见私钥、改不了内容（验签必败）、可选择性丢弃（=审查，见 R3）。

### relay-client.mjs
- 连接/注册/收发/断线重连（指数退避，上限 30s）；
- 收信封回调 → 走 vap-core 三闸（复用零改动）。

## 二、实验（experiments/phase4-experiment.mjs）

- **R1 跨"网段"通信**：两组节点（各 3 个）只经中继可达（不直连）→ 互发信封全部验签+三闸通过；
- **R2 伪造经中继**：伪造信封经中继转发 → 对端三闸拦截（中继无感知——它转发的是密文级的签名保护内容）；
- **R3 审查检测**：中继选择性丢弃节点 A 的消息 → 节点 B 在超时窗口内未收到 → 检测到"可能的审查/丢包"（证据：发送确认 vs 到达确认的对账）；诚实标注：只可检测不可防止；
- **R4 无激励基线**：中继在 50/200/500 并发连接、每连接 10 封/秒流量下，测 CPU%/内存/字节转发率 → 估算单机可服务规模（无激励中继的承载力数据）。

## 三、NAT-PUNCHING-DECISION.md（质疑零依赖教条）

| 方案 | 论点 | 代价 |
|---|---|---|
| 自研 STUN 打洞 | 零依赖纪律延续；锥型 NAT 上基本打洞可行（RFC 5389 不复杂）| 对称 NAT/CGNAT 失败率真实存在（10-30%）；打洞+保活+重绑定是长尾工程 |
| 引入 libp2p | DCUtR/circuit-relay/AutoNAT 被 IPFS+以太坊2.0 真实流量磨过 | 供应链：我们审计不了 libp2p 全部代码；依赖体积大；PeerID 身份映射（MAJOR-5 已定规范）|
| 中继优先（本阶段） | 零依赖、已实现、跨 NAT 通信立即成立 | 延迟/带宽成本；中继是中心化点（诚实标注信任边界）|

**决策**：中继模式先行（本阶段实现）；打洞决策留到"无激励基线数据"出来后——若单机中继可服务规模够信任域用，则打洞优先级降低；若不够，再启动自研 STUN 或引入 libp2p 的评估。**零依赖是强默认，不是教条——打破它需要数据，不是冲动。**

## 五、验收标准

1. R1 全部验签三闸过、R2 拦截、R3 审查可检测（证据链完整）、R4 基线数据产出；
2. 零第三方依赖；vap-core 零改动；
3. 中继不验签不解密（其无法伪造——测试：中继篡改信封 → 对端必拒）；
4. 重连退避生效（断线 5s 内重连）；
5. 结构化 JSON + 无激励基线数据表。

## 六、诚实边界

- 中继是中心化点：只见明文、不可伪造、可选择性丢弃——信任边界 = "不可信但不可作恶"，作恶=审查可被检测；
- 打洞未做（决策见 NAT-PUNCHING-DECISION.md）；
- 本机回环测试，真实跨 NAT 实测待公网环境；
- 无激励基线是单机模拟，公网带宽成本另算。
