# VAP Phase 0.5 设计：审计者信任引导（自举问题）

> 立项问题：Phase 0 的审计者是预设密钥。公网上审计者从哪来？若审计者身份免费，
> 攻击者自己造审计者给自己发凭证（自我背书），历史稀缺性崩塌。
> 假设：**审计者资格链（资格=持有更早代际凭证）+ 审计留痕（放水可追责）使自我背书不可行、放水可追责。**
> 唯一不可消除的中心化假设：创世锚（诚实标注）。

## 一、四原语设计

### 1. 创世锚（Genesis Anchor）
- 1 个预设审计者（genesis auditor），其密钥在装置内固定生成；
- 只签 gen-0 凭证；
- 诚实标注：这是自举的信任种子，是唯一中心化假设（对应比特币创世块、PGP 面对面签名的角色）。

### 2. 凭证代际（Credential Generation）
```
gen-0 凭证：由创世锚审计签名（持有者获得"被创世锚确认过工作"的历史）
gen-1 凭证：由"持有 ≥1 个 gen-0 凭证的节点"审计签名
gen-k 凭证：由"持有 ≥1 个 gen-(k-1) 凭证的节点"审计签名
```
- 审计者资格判定：签发 gen-k 凭证的审计者，必须出示自己持有的 gen-(k-1) 凭证（验签+重放验证通过）；
- 自引用禁止：审计者不能签自己同代或更早的凭证（自我背书 = 资格不足）。

### 3. 审计留痕（Audit Trail）
- 每次签名留痕：`{ auditorId, credentialId, generation, ts }` 追加到审计者的 trail 文件；
- trail 公开可查（文件即消息）；
- 放水定义：审计者签名了"重放验证不通过"的凭证。

### 4. 独立复核抽查（Audit Quality Check）
- 交叉审计独立复核轮的装置化：第三方（装置内的复核者）随机抽查任一审计者的 trail，重放验证其签过的凭证；
- 审计质量 = 抽查中验证通过的比例；放水率 > 0 即审计记录污染（可追责证据 = trail + 失败凭证对）。

## 二、实验（experiments/phase05-experiment.mjs）

- **A 合法代际链**：创世锚签 gen-0 → gen-0 持有者审计 gen-1 → gen-1 持有者审计 gen-2；全链验签+重放通过；
- **B 自我背书攻击**：攻击者无任何凭证，自造 3 个"审计者"给自己签 gen-1 → 资格不足全部拒绝；
- **C 跨代伪造攻击**：攻击者伪造一个 gen-0 凭证（编造解）→ 无法获得资格 → 后续链断；
- **D 放水攻击与追责**：合格审计者故意放水（签一个伪造凭证）→ 验证门抓出 + trail 留痕可追责（证据 = 失败凭证 + 签名者 id）；
- **E 独立复核抽查**：100 个凭证中混入放水件，复核者抽查 20%，度量检出率与误伤率。

## 三、结论判据

1. 自我背书不可行：B/C 攻击拒绝率 100%；
2. 放水可追责：D 中放水证据链完整（谁签的、签了什么、验证为何失败）；
3. 独立复核抽查有效：E 检出率 > 0 且误伤率可度量；
4. 自举成立：除创世锚外无中心化假设，代际链可无限延伸（装置内测到 gen-3）。

## 四、诚实边界

- 创世锚是中心化起点（不可消除，只能诚实标注）；
- 审计质量抽查是概率性保障，不是完备证明；
- 装置是概念验证；代际深度与信任的映射未定义；
- 复核者自身的信任同样递归（复核者的复核者……）——装置内预设，标注为开放问题。
