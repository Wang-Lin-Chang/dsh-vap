# Phase 6 公网灰度部署清单（D6）

> **诚实声明（最高优先级）**：本清单是**部署步骤清单**，不是实测报告。
> 本阶段 D1-D5 全部在**单机同进程/多实例模拟**中跑出；**公网跨机部署尚未实测**，
> 以下每一项都需在真实公网环境下逐条验证后才能标注 [已实测]。凡未实测项一律标 [未实测]。

## 1. 节点密钥（Ed25519）

| 步骤 | 操作 | 状态 |
|---|---|---|
| K1 | 每节点用 `crypto.generateKeyPairSync('ed25519')` 生成密钥对，私钥只存本节点（文件权限 600），公钥以 spki DER base64 导出 | [未实测] |
| K2 | `nodeId` 全局唯一（域名/组织前缀），写入 `peers` 列表与 `registry.json` | [未实测] |
| K3 | 密钥轮换走 `rotateKey({ oldPubKey, newPubKey, newPrivateKey })`：旧钥签变更交易 → h+2 新钥生效；轮换前预置新钥、轮换后旧钥下架 | [未实测] |
| K4 | 私钥泄露即视为 equivocation 风险：立即 rotateKey，并监控旧钥是否被用于双签 | [未实测] |

## 2. 中继 / 传输配置

| 步骤 | 操作 | 状态 |
|---|---|---|
| R1 | 信任域内共享工作区（`ledgerDir` / `inbox` / `outbox`）先走共享盘或网关同步；跨机用 HTTP 网关（复用中环 `HttpGateway`）投递信封 | [未实测] |
| R2 | 窄车道交易（`type=commit` / `type=membership`）的提案与 QC 经网关广播；默认车道（报告/任务）走 nonce 去重，不占共识带宽 | [未实测] |
| R3 | 中继为每个 `nodeId` 维护连接；PeerID↔Ed25519 身份映射沿用 Phase 1 约定（传输握手密钥与共识身份密钥分离，互不冒充） | [未实测] |
| R4 | NAT 穿透失败时走中继兜底；中继只转发不背书（押金买资源，不买信任） | [未实测] |

## 3. 创世锚发布

| 步骤 | 操作 | 状态 |
|---|---|---|
| G1 | 由 1 个预设审计者 `createGenesisAnchor()` 充当创世锚，其公钥**带外发布**（唯一中心化假设） | [未实测] |
| G2 | 新成员资格凭证由创世锚签发（gen-0），`verifyCredentialChain` 回验到创世锚 | [未实测] |
| G3 | 创世锚公钥变更需全体成员重新确认（等同于重新自举信任域） | [未实测] |

## 4. 成员加入 / 除名流程

| 步骤 | 操作 | 状态 |
|---|---|---|
| M1 | 加入：新节点持资格凭证 `proposeJoin` → 现有成员 2/3 `endorseJoin` → `submitTx` 进窄车道 → 提交于高度 h → h+2 生效 | [未实测] |
| M2 | 除名（equivocation）：`detectEquivocation` 产双签证据 → `expelByEquivocation` 打包 slash 交易上链 → 提交后签名**立即**不计入 → h+2 roster 掉表 | [未实测] |
| M3 | 主动退出：`{ op:'expel' }` 交易带本人签名 → h+2 生效 | [未实测] |
| M4 | 每次 roster 变更重算 `f = floor((n-1)/3)`、`threshold = 2f+1` | [未实测] |

## 5. 监控指标（灰度期必盯）

| 指标 | 判据 | 状态 |
|---|---|---|
| QC 达成率 | 每轮 QC 是否 ≥ 2f+1 达成；低于阈值即告警 | [未实测] |
| 视图切换率 | `onTimeout` 频率；持续活锁 = 部分同步假设被打破 | [未实测] |
| equivocation 事件数 | 每节点双签次数；>0 即触发 slash 上链 | [未实测] |
| roster 大小 / f / threshold | 成员变更后是否在所有节点同一高度原子切换 | [未实测] |
| 延迟窗口推进 | 变更提交后、生效前旧 roster 是否照常推进 2 块（无中断） | [未实测] |
| 账本哈希链 | 各节点 `committedDigest` 前缀是否一致（3-chain 提交） | [未实测] |

## 6. 回滚方案

| 步骤 | 操作 | 状态 |
|---|---|---|
| B1 | 灰度入口：先 3 节点（f=0），逐步扩到 4（f=1）、5（f=1） | [未实测] |
| B2 | 发现共识分裂 → 停写、冻结 `ledgerDir`，以多数节点已提交前缀为准重放 | [未实测] |
| B3 | 创世锚泄露 → 全量重新自举（重发 gen-0 凭证 + 重建 registry） | [未实测] |
| B4 | 中继故障 → 回退共享盘/直连；所有节点保留本地账本副本可重放 | [未实测] |

## 7. 未实测风险（诚实列出）

1. **公网全链路未实测**：本清单是步骤文档，不是实测结论；跨机延迟、丢包、分区下行为未验证。
2. **部分同步假设**：完全异步 + 拜占庭 leader 可能活锁（异步 BA 是后续题）。
3. **动态成员在大网络未覆盖**：reconfiguration 风暴、双 roster 过渡未处理——本阶段是小规模信任域简化版。
4. **≥f+1 共谋**：BFT 数学边界，只能检测不能阻止。
5. **公钥基础设施**：创世锚是唯一中心化点，其可用性与保密性未做容灾实测。
6. **军法上链只上"可判定"部分**：诚实边界的模糊部分留审计层，不进共识。
